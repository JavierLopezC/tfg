\chapter{Pruebas y Resultados\label{sec:resultados}}

\section{Comprobación de funcionalidad previa}

Antes de proceder a introducir toda la nueva funcionalidad explicada a partir del punto 4.4, y tras realizar la unificación de las dos ramas de las que se partía y la solución de los problemas de optimización explicados en 4.3, aseguramos que la funcionalidad anterior no se ha visto afectada mediante el uso de la batería de tests ya disponibles para el programa \textbf{OncoSimulR}. Esta batería de tests incluye por una lado unos tests manuales muy extensos y costosos computacionalmente, y otro grupo de tests que comprueban la funcionalidad básica del programa mediante el paquete \textbf{testthat}\cite{Testthat} del lenguaje R. Al ejecutar estos tests se detectaron una serie de errores previos al merge en una de las ramas. Los errores detectados están localizados en los tests de la funcionalidad de intervenciones, y son errores en los propios tests y no fallos de funcionalidad. Para solucionar estos errores:

\begin{itemize}
		\item Se modifica la salida del algoritmo de simulación BNB implementado en la función \textbf{nr\_BNB\_Algo5} para que incluya una lista con los tiempos de la simulación en los que se ejecutan intervenciones (esto nos permite buscar los puntos exactos donde se realizan las intervenciones en los tests). De este modo la salida de la función principal de simulación \textbf{OncoSimulIndiv} ahora incluye el campo \textbf{x\$other\$interventionTimes} con estos tiempos (donde ``x'' es la variable donde se almacena la salida de la función).
		\item Adelantamos el punto de ejecución de las intervenciones en el flujo principal del código de la simulación para que se realicen antes de rellenar las estructuras de salida. Con esto conseguimos que al actualizarse las poblaciones y \glspl{tasaNac} y muerte al final de cada ciclo de simulación, estas incluyan los cambios realizados por las intervenciones. Antes de esta modificación, los cambios que realizaban las intervenciones no se veían reflejados en las poblaciones mostradas a la salida hasta el tiempo correspondiente a la siguiente iteración de la simulación, lo que generaba un desfase entre lo que se testeaba (que emplea los datos de salida) y las poblacioes internas empleadas en la simulación (que sí incluían los cambios realizados por las intervenciones).
		\item Comentar la comprobación de totPopSize != totalPop en reduceTotalPopulation (interventions.cpp) porque al haberlo adelantado totPopSize no está actualizado.
		\item Añadimos un fragmento de código para eliminar los \glspl{genotype} con población cero después de realizar intervenciones. Las poblaciones de tamaño 0 se deben eliminar de las tablas pues estas solo contienen poblaciones existentes. 
		\item Modificamos los tests ya existentes de intervenciones para adaptarlos a estos nuevos cambios y comprobamos que todos los tests se pasan correctamente. Estas modificaciones consisten principalmente en hacer que se empleen los tiempos almacenados en \textbf{x\$other\$interventionTimes} para buscar los puntos en los que se realizan intervenciones y comprobar que estas son correctas, en lugar de buscarlas recorriendo la estructura de salida con las poblaciones en cada unidad de tiempo, pues este método no permitía un testeo correcto además de ser mucho menos eficiente.
\end{itemize}

Por último, tras implementar toda la nueva funcionalidad (explicada a partir del punto 4.4) volvemos a ejecutar toda la batería de tests  para asegurar, de nuevo, que estos cambios no han afectado al correcto funcionamiento de la funcionalidad previa. Nótese que cada vez que se ejcuta el comando ``R CMD check'' se ejcutan todos los tests de la herramienta \textbf{Testthat}\cite{Testthat}, siendo la forma habitual de operar ejecutar en orden:
\begin{enumerate}
	\item R CMD build
	\item R CMD check
\end{enumerate}

En concreto los tests que emplean la herramienta \textbf{testthat}\cite{Testthat} incluyendo un nuevo documento de tests \textbf{test.user\_var.R} que prueba la funcionalidad de las variables de usuario, y se ha ampliado el documento de tests \textbf{test.intervention.R} que incluye los tests sobre intervenciones, para añadir los casos en que estas dependen de los valores contenidos en variables de usuario. Ambos ficheros están incluidos en el directorio \textbf{tests/testthat} del repositorio\footnote{https://github.com/JavierLopezC/OncoSimul/tree/adaptive-ther/OncoSimulR/tests/testthat}. \subsection{Variables de usuario}

Cómo hemos comentado, los tests que comprueban el correcto funcionamiento de las variables de usuario están contenidos en el fichero \textbf{test.user\_var.R}. Estos tests contienen las siguientes comprobaciones:
\begin{itemize}
	\item Las variables de usuario se crean correctamente.
	\item Dos variables de usuario no pueden tener el mismo nombre.
	\item Las reglas para la actualización de las variables de usuario se crean correctamente.
	\item Dos reglas no pueden tener el mismo ID.
	\item Al ejecutarse las reglas, las variables de usuario se modifican de forma correcta (en función de la variable T).
	\item Al ejecutarse las reglas las variables de usuario se modifican de forma correcta (en función de la variable N).
	\item Al ejecutarse las reglas las variables de usuario se modifican de forma correcta (en función de las poblaciones por \gls{genotype} n\_x).
	\item Al ejecutarse las reglas las variables de usuario se modifican de forma correcta (cuando la \textit{Condition} o \textit{Action} dependen de otras variables de usuario definidas previamente).
\end{itemize}

\section{Resultados}

En esta sección vamos a comprobar que, efectivamente, los resultados obtenidos cumplen con lo esperado e, incluso, se han logrado resultados positivos que no se habían planteado inicialmente como objetivos del trabajo.

\subsection{Variables de usuario como datos de interés a la salida}
Al implementar las variables de usuario, como hemos comentado anteriormente, se permite obtener un enorme número de datos arbitrariamente complejos de la simulación a la salida. Estos pueden ser de gran interés para una mejor comprensión de lo ocurrido durante la simulación. En esta sección se van a plantear algunos ejemplo de ejecución en los que se saca partido a esta funcionalidad.

\subsubsection{Representación de la proporción de cada \gls{genotype} sobre la población total}
Comenzamos con un ejemplo muy sencillo en el que generamos un grupo de variables de usuario que almacenan la proporción de cada \gls{genotype} existente sobre el total de la población, es decir, matemáticamente cada una de estas variables es, para cada \gls{genotype} ``X'':
$$proporcionX = n\_X/N$$
Dónde ``n\_X'' es el tamaño de población correspondiente al \gls{genotype} X (o sea, el número de células del genotipo X), y ``N'' la población total (el número total de células).

Con estas variables de usuario definidas iniciamos una simulación con 5 \glspl{genotype}: \textbf{WT} (el inicial, sin \glspl{mut}), \textbf{A}, \textbf{B}, \textbf{A,B} y \textbf{A,C}. Asignamos a cada uno de ellos sus \gls{fitness} y sus poblaciones iniciales (estos detalles se pueden ver en el código adjunto en el apéndice A.1 para ejecutar esta simulación), e iniciamos la simulación llamando a \textbf{OncoSimulIndiv}. En este caso simularemos tan solo un tiempo de 10 unidades, pues es suficiente para ver los datos que nos proporcionan las variables de usuario.

Ahora representamos gráficamente los resultados obtenidos en las poblaciones de los \glspl{genotype} y en las variables de usuario (figuras 5.1 y 5.1).

\subsubsection{Representación de la diferencia entre la \gls{tasaNac} y muerte}
Vamos ahora con otro ejemplo para analizar más profundamente el uso de variables de usuario. En este caso las que vamos a definir son variables que contengan el valor de la diferencia entre la \gls{tasaNac} y muerte de los distintos \glspl{genotype}. Este valor, por tanto, nos mostrará si se debería esperar que la población de un determinado \gls{genotype} crezca (si la diferencia es positiva) o disminuya (si es negativa). La fórmula para calcular estas variables de usuario es muy sencilla:
$$diferenciaTasasX = b\_X - d\_X$$
Dónde ``b\_X'' es la \gls{tasaNac} correspondiente al \gls{genotype} X, y ``d\_X'' la de muerte.
Del mismo modo que en el ejemplo anterior, establecemos los datos de la simulación (visibles en el apéndice A.2 en el código para reproducir el ejemplo) que en este caso contará con 3 \glspl{genotype} \textbf{WT}, \textbf{A} y \textbf{B}, y, para que los datos de las tasas sean variables y más interesantes de analizar, definiremos el \gls{fitness} como dependiente de las frecuencias de los \glspl{genotype}, funcionalidad que también permite la herramienta \textbf{OncoSimulR}.

Representamos los resultados obtenidos para las variables de usuario que representan la diferencia de tasas y la evolución poblacional (figuras 5.3 y 5.4).

\subsection{Terapia Adaptativa}
Procedemos ahora a analizar el resultado de la funcionalidad correspondiente al objetivo principal de este trabajo, que es lograr simular la terapia adaptativa. Para ello empleamos una serie de ejemplos de ejecución que nos permitirán ver el funcionamiento de esta.

\subsubsection{Selección de tratamiento según el \gls{genotype} más adaptado}
Comenzamos con un ejemplo en el que simulamos un tratamiento en un paciente con cáncer. En este caso en el tumor aparecen tres \glspl{genotype}, el \gls{genotype} original \textbf{WT} sin \glspl{gen} mutados, y los \glspl{genotype} \textbf{A} y \textbf{B} con los \glspl{gen} A y B mutados respectivamente. En este ejemplo simularemos un tratamiento que varía para enfocarse en el \gls{genotype} con más velocidad de crecimiento y que, por tanto más posibilidades tiene de desarrollarse. Para ello partimos del mismo ejemplo que en el punto anterior (5.3.2) en el que calculamos la diferencia de las \glspl{tasaNac} y muerte, para de esta forma estimar cual es el \gls{genotype} con más posibilidades de proliferar. Además añadimos un mínimo poblacional de 1000 células para detectar determinado \gls{genotype}, es decir, que si la población de un \gls{genotype} no es superior a 1000 no se tratará, pues no se considera suficiente para ser detectado.

Tras esto definimos una serie de intervenciones para minimizar el desarrollo del \gls{genotype} que tenga dicho valor más alto. Estas intervenciones las definimos del siguiente modo:

\begin{R}
interventions <- list(
    list(ID           = "i1",
        Trigger       = "genADiff > genBDiff and genADiff > genWTDiff",
        WhatHappens   = "n_A = n_A*0.5",
        Periodicity   = 10,
        Repetitions   = Inf
    ),list(ID           = "i2",
        Trigger       = "genBDiff > genADiff and genBDiff > genWTDiff",
        WhatHappens   = "n_B = n_B*0.5",
        Periodicity   = 10,
        Repetitions   = Inf
    )
)
\end{R}

\subsubsection{Simulación de situación verosímil}
Por último vamos a simular un escenario complejo de terapia adaptativa intentando acercarnos lo máximo posible a lo que podría ocurrir en un caso real. Para ello establecemos en qué consistiría esta terapia adaptativa aplicable en la realidad, de modo similar a los ejemplos presentes en los artículos de Hansen \cite{Hansen1}\cite{Hansen2}\cite{Hansen3}:
\begin{enumerate}
	\item Cada cierto tiempo el paciente tiene una revisión dónde se analiza el progreso de su \gls{tumor}.
	\item Si se detectan unos valores anormales en las poblaciones de \glspl{genotype} mutados se comienza un tratamiento base para tratar de frenar el avance de este.
	\item Si se observa un crecimiento anormalmente grande de un tipo determinado de células se cambia el tratamiento que se estaba aplicando hasta el momento por otro más enfocado a las células de ese tipo.
	\item Si el tumo sobrepasa un cierto tamaño preestablecido se plantea la necesidad de realizar una intervención quirúrgica para tratar de eliminarlo.
\end{enumerate}
Para este ejemplo además consideraremos preocupantes las células de \glspl{genotype} distintos al \textbf{WT}, pues este es el inicial sin \glspl{mut}, y, por tanto, no se considera peligroso.

Todo el código para reproducir este ejemplo se encuentra en el apéndice A.4.

Procedemos entonces a tratar de simular este escenario con 3 \glspl{genotype} \textbf{WT}, \textbf{A} y \textbf{B}, para ello definimos en primer lugar una serie de variables de usuario que serán:
\begin{itemize}
	\item \textbf{measure}: flag que determina si toca realizar una medición o no (revisión del paciente).
	\item \textbf{lastTime}: almacena el último tiempo en que se ha realizado una medición.
	\item \textbf{lastMeasuredA}: valor de la población del \gls{genotype} A en la última medición.
	\item \textbf{lastMeasuredB}: valor de la población del \gls{genotype} B en la última medición.
	\item \textbf{previousA}: valor de la población del \gls{genotype} A en la medición anterior (permite luego calcular las diferencias para ver el crecimiento).
	\item \textbf{previousB}: valor de la población del \gls{genotype} B en la medición anterior (permite luego calcular las diferencias para ver el crecimiento).
	\item \textbf{treatment}: variable que determinará el tratamiento a aplicar.
\end{itemize}

Estas las modificaremos de acuerdo a las siguientes reglas:
\begin{enumerate}
	\item Si ``current time (T)'' - \textbf{lastTime}  < 10 (no han pasado 10 segundos):  \textbf{measure} = 0 (no hay que medir).
	\item Si T - \textbf{lastTime}  > 10 (han pasado 10 segundos):  \textbf{measure} = 1 (hay que medir) y \textbf{lastTime} = T.
	\item Si \textbf{measure} == 1 (hay que medir): \textbf{previousA} = \textbf{lastMeasuredA}; \textbf{previousB}=\textbf{lastMeasuredB}; \textbf{lastMeasuredA} = n\_A y \textbf{lastMeasuredB} = n\_B (almacenamos los datos medidos).
		\item Si no se cumple ninguna de las condiciones siguientes (Si true): \textbf{treatment} = 0.
	\item Si \textbf{lastMeasuredA} + \textbf{lastMeasuredB} > 100 (\gls{tumor} detectable): \textbf{treatment} = 1.
	\item Si \textbf{lastMeasuredA} - \textbf{previousA} > 500 (\textbf{A} ha crecido mucho): \textbf{treatment} = 2.
	\item Si \textbf{lastMeasuredB} - \textbf{previousB} > 500 (\textbf{B} ha crecido mucho): \textbf{treatment} = 3.
	\item Si \textbf{lastMeasuredA} - \textbf{previousA} > 500 AND \textbf{lastMeasuredB} - \textbf{previousB} > 500 (\textbf{A} y \textbf{B} han crecido mucho): \textbf{treatment} = 4.
\end{enumerate}

Ahora podemos definir las intervenciones en base al valor de \textbf{treatment} del siguiente modo:
\begin{R}
interventions <- list(
    list(ID           = "basicTreatment",
        Trigger       = "treatment == 1",
        WhatHappens   = "N = 0.8*N",
        Periodicity   = 10,
        Repetitions   = Inf
    ),list(ID           = "treatmentOverA",
        Trigger       = "treatment == 2 or treatment == 4",
        WhatHappens   = "n_B = n_B*0.3",
        Periodicity   = 20,
        Repetitions   = Inf
    ),list(ID           = "treatmentOverB",
        Trigger       = "treatment == 3 or treatment == 4",
        WhatHappens   = "n_B = n_B*0.3",
        Periodicity   = 20,
        Repetitions   = Inf
    ),list(ID           = "intervention",
        Trigger       = "lastMeasuredA+lastMeasuredB > 5000",
        WhatHappens   = "N = 0.1*N",
        Periodicity   = 70,
        Repetitions   = Inf
    )
)
\end{R}

Establecemos que el tratamiento básico se puede realizar cada 10 unidades de tiempo, los específicos sobre \textbf{A} y \textbf{B} al ser más agresivos establecemos que sólo se pueden realizar cada 20 unidades de tiempo, por último, la intervención quirúrgica no se puede realizar de forma muy habitual, por lo que establecemos que puede ocurrir cada 70 unidades, y se realizará cuando el conjunto de células peligrosas supere 5000.

Con todo esto comenzamos la simulación, obteniendo el siguiente resultado poblacional:

\begin{figure}[htp]
	\centering
	\includegraphics[width=10cm]{imagenes/resultsAT2}
	\caption{Evolución poblacional. Ejemplo 2 terapia adaptativa}
	\label{fig:populationAT2}

Podemos ver como a partir de aproximadamente el tiempo 100 comienza a haber pequeñas bajadas bruscas en todos los \glspl{genotype} al mismo tiempo, correspondientes al tratamiento base. Luego alrededor del tiempo 150 el \gls{genotype} \textbf{B} aumenta demasiado y sufre una bajada más grande por su tratamiento específico; y, finalmente, alrededor del tiempo 160-170 las poblaciones \textbf{A} y \textbf{B} han crecido lo suficiente como para que se lleve a cabo una intervención, por lo que se desploman todas las poblaciones.

Este es por tanto un clarísimo ejemplo de una terapia adaptada al progreso del \gls{tumor}, y por tanto vemos que se ha logrado con éxito la simulación de la terapia adaptativa.
